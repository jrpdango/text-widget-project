## Decisions locked in

| Area | Choice |
|---|---|
| Framework | Next.js **16.4.3** (latest stable), App Router, React 19.3.1, TypeScript |
| API | Next.js Route Handlers in the same app: `/api/widgets`, `/api/widgets/[id]`, `/api/health` |

| Validation | Zod **4.6.7** |

| Env | No `.env`, no dotenvx. `lib/db.ts` defaults to `mongodb://127.0.0.1:27017/text-widgets`; Compose sets `MONGODB_URI=mongodb://mongo:27017/text-widgets` |

| Mongo | No auth, `mongo:8`, port `27017` published to host, named volume |
| Port | App on `3000` |
| Tests | Keep Vitest; mock `@/lib/api` for UI, mock the Mongoose model for route handlers |

## Target architecture

```text
Browser (React Client Components)
        │  fetch('/api/widgets...')
        ▼
Next.js Route Handlers (Node runtime)
        │  Mongoose (server-only import)
        ▼
MongoDB container
```

The browser never imports Mongoose. `src/lib/db.ts` and the model will import `server-only`, so a client component that accidentally imports them fails at build time. The only client-facing data layer is `src/lib/api.ts`, which speaks HTTP.

`src/lib/models/Widget.ts`:
```ts
const widgetSchema = new Schema(
  {
    id: { type: String, required: true, unique: true, index: true },
    content: { type: String, default: '', maxlength: 100_000 },
  },
  { timestamps: true, versionKey: false, id: false },
```

`id: false` is important: it disables Mongoose's built-in `id` virtual so the real `id` path works.

## 3. REST API contract

| Method | Path | Body | Success | Failure |
|---|---|---|---|---|
| `GET` | `/api/widgets` | — | `200 WidgetData[]`, newest first | `503` |
| `POST` | `/api/widgets` | `{ "content"?: string }` | `201 WidgetData` | `400`, `503` |
| `GET` | `/api/widgets/:id` | — | `200 WidgetData` | `400`, `404`, `503` |
| `PATCH` | `/api/widgets/:id` | `{ "content": string }` | `200 WidgetData` | `400`, `404`, `503` |
| `DELETE` | `/api/widgets/:id` | — | `204` | `400`, `404`, `503` |
| `GET` | `/api/health` | — | `200 { "status": "ok" }` | `503` |

Rules:
- `id` must be a UUID (`z.uuid()`), otherwise `400 invalid_id`.
- `content` max **100,000** characters, otherwise `400 validation_error`.
- Unknown/extra body fields rejected (`strict()`).
- Malformed JSON → `400 invalid_json`.
- Missing widget → `404 not_found`.
- Mongo unreachable → `503 database_unavailable`.
- Unexpected errors → `500 internal_error`, logged server-side only.

Error body:
```json
{ "error": { "code": "validation_error", "message": "content must be 100000 characters or fewer" } }
```

Route implementation notes:
- `export const runtime = 'nodejs'`, `export const dynamic = 'force-dynamic'`, `export const revalidate = 0`.
- Dynamic params are a Promise in Next 15+: `{ params }: { params: Promise<{ id: string }> }`, then `const { id } = await params`.
- Use plain `Request`/`Response` (not `NextRequest`) so tests don't need Next internals.
- `POST` generates `crypto.randomUUID()` server-side; the client never chooses an id.
- `DELETE` returns `new Response(null, { status: 204 })`.
- `GET /api/health` pings Mongo and returns `503` when the DB is down; Compose uses it as the app healthcheck.

## 4. Client changes

**`src/lib/api.ts`** (client-safe, no Mongoose):
- `fetchWidgets()`, `createWidget(content)`, `updateWidget(id, content)`, `deleteWidget(id)`.
- Parses the error envelope into an `ApiError` with `status`, `code`, `message`.
- `cache: 'no-store'`.

**`src/hooks/useWidgets.ts`** rewrite:
- Initial state `widgets: []`, `status: 'loading' | 'ready' | 'error'`; fetch on mount, never touch localStorage.
- Add widget: insert an optimistic temp widget at the top, focus it, `POST` it. On success replace the temp id with the server id. If the create fails, keep the widget locally in an error state and retry the create with the current content.
- Edit: update local content immediately; debounce 600 ms per widget; set `saving` → `saved` or `error`; track a per-widget version so a stale response can't overwrite newer text.
- Retry: resend the current content for that widget.
- Delete: optimistic removal; on failure restore the widget at its original position with an error state and a retry action.
- Flush pending saves on blur and on unmount; best-effort flush on `pagehide` using `keepalive`.
- Last-write-wins concurrency; no locking.

**UI:**
- `TextWidget` gains `saveState` and `onRetry` props; footer shows `Saving… / Saved / Couldn't save` plus a Retry button, with `aria-live="polite"`.
- `App` shows a loading state while the first fetch runs, a full-page error card with Retry if it fails, and the existing empty state once loaded.
- Copy updates: remove "Everything stays in your browser" and "Saved locally"; use "Stored in MongoDB" / "Synced".
- Markdown behavior, character count, preview toggle, focus behavior, and theme toggle stay unchanged.

**Theme / SSR:**
- `useTheme` becomes SSR-safe: no `window` access during render; read localStorage and `matchMedia` in effects.
- A tiny inline `<script>` as the first child of `<body>` in `layout.tsx` sets `data-theme` and `color-scheme` before paint (replaces the old `index.html` script). `suppressHydrationWarning` on `<html>`.
- `App.tsx` gets `'use client'`; `page.tsx` stays a server component that renders it.
- Move `index.css`, `ui.css`, and `App.css` imports into `layout.tsx` (global CSS must be imported from the root layout in App Router).

## 9. Notes / risks

- **Unload flush:** `fetch(..., { keepalive: true })` is capped around 64 KB by browsers, while content is allowed up to 100 KB. Debounced autosave + blur flush covers the normal case; unload flush is best-effort for large notes.
- **Concurrency:** single shared list, last-write-wins. Two tabs editing the same widget can overwrite each other.
- **No auth:** anyone who can reach the app can read/write all widgets; Mongo is exposed on 27017 without credentials. Fine for local use, not for public deployment.
- **Next 16 specifics:** `reactCompiler` is top-level, `next lint` is gone (use `eslint .`), route `params` is a Promise, and `serverExternalPackages: ['mongoose']` avoids bundling issues.
- **Hydration:** widget loading starts in an effect and theme reading moves to effects, so SSR and the first client render match.
- **Testing:** the Mongoose model is mocked, so CI never needs a running MongoDB.

## Revised testing approach

### Core rules

1. **Mock only the boundary, never the unit under test.**
   - UI tests mock `@/lib/api` (the network boundary), not `useWidgets` or `App`.
   - API tests mock `@/lib/db` and `@/lib/models/Widget` (the storage boundary), not the route handlers or Zod schemas.
   - Never mock the function whose behavior the test is claiming to verify.

2. **Expected values must be independent of the implementation.**
   - Hardcode expected JSON, UUID regexes, boundary lengths, and timestamps in the test.
   - Do **not** import `serializeWidget`, `MAX_CONTENT_LENGTH`, or the Zod schema to build expectations — if the implementation is wrong, the test would agree with it.
   - Example: use `100_000` / `100_001` literals in the test, not a shared constant.

3. **Every test must have a plausible failure mode.**
   - Before keeping a test, ask: *what single-line bug would make this fail?* If there's no answer, rewrite or delete it.
   - Reject weak assertions: `toBeDefined()`, `toBeInTheDocument()` on always-present elements, `toHaveBeenCalled()` with no payload, snapshots as the only assertion, and tests that only assert a mock returned what the test told it to return.

4. **Assert observable behavior, not implementation echoes.**
   - API: status code **and** parsed body **and** model call arguments where the contract matters.
   - UI: rendered DOM/ARIA state **and** the outgoing API payload; not just that a mock was invoked.
   - Await async transitions with `findBy*` / `waitFor`; never let a test finish before the behavior happens.

5. **Include negative and boundary cases.**
   - Invalid UUID, missing widget, malformed JSON, extra fields, 100,001 characters, DB unavailable, API rejection, delete failure, retry failure.
   - A route that always returns `200` must fail at least one test.

### Anti-tautology examples

**Bad — tests the mock, not the app:**
```ts
api.fetchWidgets.mockResolvedValue([widget]);
render(<App />);
expect(await api.fetchWidgets()).toEqual([widget]);
```

**Good — tests what the user sees:**
```ts
api.fetchWidgets.mockResolvedValue([widget]);
render(<App />);
expect(await screen.findByDisplayValue('Remember me')).toBeInTheDocument();
```

**Bad — debounce removal still passes:**
```ts
await user.type(textarea, 'abc');
expect(api.updateWidget).toHaveBeenCalled();
```

**Good — fails if debounce is removed or fires too early:**
```ts
await user.type(textarea, 'abc');
expect(api.updateWidget).not.toHaveBeenCalled();
await vi.advanceTimersByTimeAsync(599);
expect(api.updateWidget).not.toHaveBeenCalled();
await vi.advanceTimersByTimeAsync(1);
expect(api.updateWidget).toHaveBeenCalledTimes(1);
expect(api.updateWidget).toHaveBeenCalledWith('widget-1', 'abc');
```

**Bad — serializer bug is invisible:**
```ts
Widget.find.mockResolvedValue([doc]);
const body = await (await GET()).json();
expect(body).toEqual([serializeWidget(doc)]); // same code as production
```

**Good — hardcoded contract, strips `_id`, ISO strings:**
```ts
const body = await (await GET()).json();
expect(body).toEqual([
  {
    id: '11111111-1111-4111-8111-111111111111',
    content: 'Hello',
    createdAt: '2026-01-02T03:04:05.000Z',
    updatedAt: '2026-01-02T03:04:05.000Z',
  },
]);
expect(body[0]).not.toHaveProperty('_id');
```

**Bad — sorting is untestable because the mock is pre-sorted:**
```ts
Widget.find.mockResolvedValue([newer, older]);
// route could omit .sort() and this still passes
```

**Good — mock returns deliberately unsorted data and assert the query:**
```ts
const lean = vi.fn().mockResolvedValue([older, newer]);
const sort = vi.fn().mockReturnValue({ lean });
Widget.find.mockReturnValue({ sort });

const body = await (await GET()).json();
expect(sort).toHaveBeenCalledWith({ createdAt: -1, _id: -1 });
expect(body.map((w) => w.id)).toEqual([newer.id, older.id]);
```

### Test matrix with intended failure modes

| Test | Must fail if… |
|---|---|
| Initial load shows loading, then API widgets | fetch effect removed, or result ignored |
| Add widget appears before POST resolves | optimistic insert removed |
| New widget is focused and first | prepend/focus logic removed |
| Typing sends exactly one PATCH after 600 ms | debounce removed, timer too short, or per-keystroke save |
| Blur flushes pending save immediately | blur handler removed |
| Remount shows server data | app reads localStorage instead of API |
| Save failure shows inline error + Retry; Retry re-PATCHes | error state or retry wiring removed |
| Delete failure restores the widget | rollback removed |

| Theme attribute/localStorage updates | theme effect removed |
| Invalid stored theme ignored | theme validation removed |
