# Plan: Text Widgets

## Locked decisions

- **Stack:** existing Vite + React 19 + TypeScript template, plain CSS with custom properties.
- **Persistence:** widgets, text, and theme choice in `localStorage`. No backend.
- **Widgets:** one-column cards, newest first, auto-focus the new textarea, unlimited length with a live character count, immediate delete, no title/timestamp.
- **Markdown:** GFM via `react-markdown` + `remark-gfm`; raw HTML never rendered; images stripped; links open in a new tab with `rel="noopener noreferrer"`; fenced code blocks syntax-highlighted with a Monokai theme.
- **Theme:** two-way Light/Dark toggle, defaults to OS preference, follows OS changes until the user toggles, then saves and honors the explicit choice on reload.
- **Docker:** multi-stage build served by unprivileged Nginx on port `8080`; no compose file.
- **Tests:** Vitest + Testing Library + jsdom, behavioral coverage, written first and verified failing before implementation.

### State and persistence

- `Widget { id: string; content: string }`, IDs from `crypto.randomUUID()`.
- Keys: `text-widgets:v1` and `text-widgets:theme`.
- Hydration validates the stored shape; malformed or unavailable storage falls back to an empty list without crashing.
- Content is persisted on each change by serializing the widget array; `localStorage` errors (quota/private mode) are caught.
- New widgets start empty in Write mode at the top of the list and receive focus.
- Preview mode is per widget and resets to Write on reload.

### Theme

- An inline script in `index.html` applies the resolved theme before first paint to avoid a light flash.
- Resolution order: saved choice → `prefers-color-scheme` → light.
- With no saved choice, a `matchMedia` listener keeps the app in sync with OS changes. Once toggled, the choice is saved and the listener is ignored.
- Theme is expressed as `data-theme="light|dark"` on `<html>`, with both palettes defined as CSS custom properties.

### Monokai palettes

- **Dark (Monokai Pro):** `#2d2a2e` background, `#403e41` surfaces, `#fcfcfa` text, `#727072` muted, `#ff6188` / `#ab9df2` / `#78dce8` accents.
- **Light (Monokai Pro Light):** `#faf4f2` background, `#29242a` text, `#e14775` / `#7058be` / `#1c8ca8` accents.
- Highlight.js token colors mapped to the same accent set; no external CSS or CDN dependency.

### UI behavior

- Sticky header: **Text Widgets**, primary **Add widget** button, theme toggle with an accessible label.
- Empty state when there are no widgets.
- Each card: Write/Preview segmented toggle, delete button (`aria-label`), textarea with fixed reasonable height for very long content, live `N characters` count, and preview pane.
- Markdown renders headings, lists, blockquotes, tables, task lists, strikethrough, autolinks, inline code, and fenced code.
- No raw HTML execution; `<img>` nodes render nothing; destructive links are hardened via `target="_blank"` / `rel`.
- Keyboard-accessible controls and visible focus states throughout.

## Test plan (written first, red → green)

Tests assert user-visible behavior and persisted state rather than internal implementation:

1. Clicking **Add widget** creates an empty textarea and removes the empty state.
2. Adding twice places the newest widget first.
3. A new widget receives focus.
4. Typing **1,000+ characters** preserves the full content and shows the correct count.
5. Character count updates as text changes.
6. Deleting one widget removes only that widget.
7. Write/Preview toggle is per widget and renders Markdown (`#`, lists, bold) in preview.
8. GFM table and task-list syntax renders in preview.
9. Raw HTML such as `<script>` / `<b>` is not rendered as markup.
10. Markdown images are not rendered.
11. Links receive `target="_blank"` and `rel="noopener noreferrer"`.
12. Fenced code blocks receive syntax-highlight token markup.
13. Widgets hydrate from `localStorage` after unmount/remount.
14. Malformed stored data is ignored safely.
15. Theme defaults to the OS preference, follows `matchMedia` changes, and toggles to the opposite theme.
16. An explicit theme choice persists across remount and suppresses later OS changes.
17. Toggling back to the original theme still persists correctly.
18. No-widget and deletion-to-empty states render correctly.

TDD workflow: add failing tests first, run them and confirm they fail for the missing behavior (not setup errors), then implement until all pass. No tautological assertions like "renders what state contains"; assertions target DOM output, storage contents, focus, and media-query behavior.
